# 배포 환경 증상 → 레포 밖 원인 트리아지 체크리스트 (BE)

배포 환경에서만 재현되는 증상(로컬은 정상)을 추적할 때, **BE 레포 코드만 보면 놓치는 "레포 밖" 원인**을 빠짐없이 점검하기 위한 체크리스트다. be-harness가 "배포 증상 디버깅" 작업을 라우팅하면, 보고 단계에서 이 파일을 로드해 **증상에 해당하는 항목만** 골라 체크리스트로 제시한다.

## 사용 원칙
- 레포 안에서 고친 것과 **레포 밖에서 확인할 것**을 분리해 보고. 레포 밖 항목은 "사용자 확인 필요" 액션으로 명시.
- 증상별로 관련 항목만 추린다. 각 항목에 **확인 명령/위치**와 **정상 기준**을 적는다.

## 증상 → 점검 매트릭스

### A. WebSocket 시그널링(`/socket`) 연결/유지 실패 — REST는 정상
- [ ] **호스트 nginx `/socket` Upgrade 헤더**: `proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade"; proxy_http_version 1.1;` 존재? WS 핸드셰이크 101 승격 필수.
- [ ] **`proxy_read_timeout`**: WS 유휴 끊김 방지로 길게 설정됐나.
- [ ] **컨테이너 헬스/포트**: BE 컨테이너가 8080에서 정상 기동? `docker compose ps`, `docker logs`로 기동 로그·핸드셰이크 로그(`WebSocket 핸드쉐이크 roomId:`) 확인.
- [ ] **세션 한도/버퍼**: `WebSocketConfig`의 `setMaxTextMessageBufferSize` 등 컨테이너 설정과 실제 메시지 크기.

### B. CORS / 인증으로 API 차단
- [ ] **운영 CORS 오리진**: `application-prod.yml` 또는 `CorsConfig`의 허용 오리진에 실제 배포 도메인이 포함됐나. 프로파일이 `prod`로 떴나(`SPRING_PROFILES_ACTIVE`).
- [ ] **프록시 경유 오리진/헤더**: 호스트 nginx가 `/api`를 프록시할 때 `Origin`/`Host`/`X-Forwarded-*`를 보존하나.

### C. 환경/설정 불일치
- [ ] **활성 프로파일**: 컨테이너가 `prod` 프로파일로 떴는지(`docker compose`의 env, `SPRING_PROFILES_ACTIVE=prod`).
- [ ] **환경변수/시크릿**: DB·외부 연동 자격증명이 배포서버에 주입됐나(GHCR 이미지엔 안 굽힘).
- [ ] **인메모리 상태 휘발**: 재배포(`up -d`로 컨테이너 교체) 시 채팅방·세션 상태가 전부 사라짐 — "방이 갑자기 없어짐" 증상의 원인일 수 있음(현재 상태가 인메모리라 정상 동작이나, 사용자에게 한계로 안내).

### D. 배포는 됐는데 옛 버전이 동작
- [ ] **GHCR 이미지 태그**: `docker compose`가 참조하는 태그가 최신 빌드인가. 러너가 새 이미지를 실제 pull & `up -d` 했나(self-hosted 러너 로그).
- [ ] **빌드 산출물**: 멀티스테이지 빌드에서 최신 jar가 이미지에 들어갔나(plain jar 비활성 확인).

### E. 동시성/부하에서만 깨짐
- [ ] **공유 가변 상태 경합**: 채팅방·세션 맵 동시 접근, `ThreadLocal` 핸드셰이크 값 누수, 세션 정리 타이밍. 다중 접속 시 재현되는지.

## 보고 형식 (체크리스트 자동 생성)
디버깅 보고 말미에 출력:

```
## 레포 밖 점검 항목 (내가 못 고침 — 사용자 확인 필요)
증상 분류: <A/B/C/D/E 중>
- [ ] <항목> — 확인: `<명령/위치>` — 정상 기준: <…>
...
다음 행동: <어떤 것부터 확인할지>
```

> WS 프록시·TLS는 FE/호스트 nginx와 공통 — 교차 레포 증상이면 관제탑(webvideochat-control)으로 올려 양쪽을 함께 본다.
